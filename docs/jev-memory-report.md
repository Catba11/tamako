# Tamako 记忆流水线 × Jev 决策引擎 — 实验报告

日期：2026-09-18 ｜ 分支：`jev-memory`（worktree `~/tamako-jev`）｜ 配套设计文档：`docs/jev-memory-benchmark.md`

> 本报告只含聚合指标与匿名化统计，不含任何群聊原文。

## 1. 实验设置

- **对象**：Tamako 记忆巩固（digest）与检索（recall）流水线中的三处 LLM 判断点：
  - J1 解析确认（向量相似度 ≥ 0.88 的候选对 → 同一实体？，生产阈值 0.88）
  - J2 合并裁决（KNN ≥ 0.90 候选对 → same/related/different，生产阈值 0.90）
  - J3 相关性门控（≤40 候选记忆 → 选 ≤5 条注入，生产 cap 40 / 注入 5）
- **引擎**：`typesafe/jev-1.13-20260917`（OpenRouter Decisions API），noul/choice 原语 + 扇出聚合，seed 0。
- **参照模型**（生产保真 prompt 复刻）：digest 侧 `z-ai/glm-5.3-flash`，gate 侧 `deepseek/deepseek-v4.1-flash`。
- **金标**：分析者（LLM）标注 192 条（uc1a 60、uc1b 60、uc2 60、uc3 12 窗 480 候选），逐条阅读原始中文上下文标注，未经人类复核；合成套件 uc1s/uc3s 自带构造金标。
- **数据**：Mac 旧快照副本，8 群 365MB；51,109 条记忆边（edge-id 连接 51,109/51,109 无丢失）、uc1 候选 7,592 对（≥0.88 共 262、0.75–0.88 共 7,330）、uc2 134 对、uc3 92 窗口（36 注入对齐）。
- **运行**：桌面专用 worktree，只读打开数据副本；生产服务与 `/var/lib/tamako` 全程未触碰。全量运行一次通过，8 套件 Jev 侧 0 错误。

## 2. 总体结论（TL;DR）

1. **中文校准：真实窗口轻度偏高自信，合成窗口达标（UC-5 主问题）**：真实数据金标子集（600 问：uc1a 60 + uc1b 60 + uc3 480）ECE 0.101，约为官方英文基准（0.036–0.053）的两倍，主要来自确认带与门控的偏高自信（uc1a ECE 0.133、uc3 0.102）；合成构造子集（4,300 问）ECE 0.040 达标。zh→en 翻译判定翻转率仅 6.7%。**结论：无灾难性 CJK 失效，但真实中文群聊上概率带 ~0.1 ECE 的偏高自信，阈值决策需留裕量。**
2. **digest 侧（J1/J2）可直接用**：uc1a/uc1b 对分析者金标准确率均 0.967，AUROC ≥ 0.976，0.5 阈值即最优或近最优；60 例金标中假阳性仅 2 例、假阴性 0。
3. **gate 侧（J3）必须用排名而非阈值**：Jev 对"是否值得注入"类问题概率系统性偏低（金标选中候选均值仅 0.36），p>0.5 规则 92 窗只选出 40 条（0.43 条/窗，生产约 0.83 条/窗）；但**排名质量很好**——金标选中候选 100% 落在 Jev 概率 top-5 内，合成埋点 recall@5 = 0.925。建议 top-k 策略。
4. **Jev 与生产实际注入零重合**：36 个注入对齐窗口中，生产注入的 76 条边无一进入 Jev top-5。结合候选列表污染（见 §11），提示生产现状的注入选择本身噪声大。
5. **UC-2 choice 存在标签塌缩**：134 例中 Jev 判 related 126、same 8、different 0——"different" 选项实际不可达。

## 3. UC-1a：确认带判断（sim ≥ 0.88，n=262）

| 指标 | vs 分析者金标 (n=60) | vs 参照模型 (n=260/262) |
|---|---|---|
| Accuracy@0.5 | 0.967 | 0.935 |
| ECE | 0.133 | 0.120 |
| Brier | 0.047 | 0.050 |
| AUROC | 0.976 | 0.969 |
| Log-loss | 0.186 | 0.194 |

- 金标混淆（@0.5）：FP=2，FN=0；金标 yes 率 11.7%（60 例中 7 例真同一实体）。阈值扫描最优为 0.50 本身。
- 参照模型缺失 2 条（API 空内容异常，见 §14）。
- 延迟：均值 0.249s，p95 0.545s；成本 $0.0056（262 请求）。

|---|---|---|
| Accuracy@0.5 | 0.967 | 0.956 |
| ECE | 0.100 | 0.105 |

## 5. UC-1s：构造金标合成对（n=300，100% 金标）

| 类别 | Accuracy@0.5 |
|---|---|
| same（昵称/缩写/翻译/改写规则变换） | **0.85** |
| hard-different（同群同类近邻对） | 1.00 |
| easy-different（跨群随机对） | 1.00 |

- 唯一弱点：规则构造的"同一实体"对有 15% 被判否——改写/翻译类变换是 Jev noul 的相对短板；不同实体判别完美。

## 6. UC-2：合并裁决三分类（n=134）

| 指标 | vs 分析者金标 (n=60) | vs 参照模型 (n=132/134) |
|---|---|---|
| Accuracy | 0.933 | 0.515 |
| Macro-F1 | 0.571 | 0.427 |

- Jev 预测分布（134 例）：related 126、same 8、**different 0**。
- 金标混淆：related 54 例 → 53 对 1 错（错成 same）；same 4 例 → 3 对 1 错；different 2 例 → 0 对（均判 related）。
- 与 glm 参照分歧大（一致率 0.515）：glm 更倾向判 same。**operational 影响有限**：生产合并只对 same 行动，Jev 的 same 精度在金标中 3/4；但"different 不可达"意味着不能用该 choice 做反向过滤。

## 7. UC-3：逐候选相关性门控（92 窗口，3,680 候选）

| 指标 | 数值 |
|---|---|
| vs 分析者金标（12 窗 / 480 候选）acc / ECE / AUROC | 0.975 / 0.102 / 0.985 |
| **top-5 排名 vs 金标：Precision / Recall** | **0.217 / 1.000** |
| 金标选中候选平均概率 vs 未选中 | 0.361 vs 0.114 |
| 注入对齐（p>0.5 选中 ∩ 生产实际注入 76 条） | **命中 0**（P=0，R=0） |
| 注入对齐（top-5 含任一注入边的窗口） | **0 / 36** |

- 金标 13 个选中候选的 Jev 概率：0.19–0.68，仅 2 个 > 0.5 → **阈值规则失效、排名有效**的直接证据。
- 参照（deepseek 门控复刻）：33/92 窗有非空选择（共选 107 候选），19 窗明确空选，40 窗参照调用失败；Jev 对 deepseek 选中候选的同意率仅 22.4%——两个门控判断体系差异巨大，金标口径（acc 0.975 / recall@5 1.0）更可信。

## 10. UC-5：中文校准总评

| 聚合池 | n_q | n_labeled | Accuracy@0.5 | ECE | Brier | AUROC |
|---|---|---|---|---|---|---|
| 真实数据金标子集（uc1a 60 + uc1b 60 + uc3 480 候选） | 600 | 600 | 0.973 | **0.101** | 0.029 | 0.983 |
| 合成构造金标子集（uc1s 300 + uc3s 4,000） | 4,300 | 4,300 | 0.978 | 0.040 | 0.017 | 0.987 |
| 全体聚合（驱动器 uc5 口径，88% 为合成） | 4,900 | 4,900 | 0.978 | 0.044 | 0.018 | 0.977 |

> 口径警示：驱动器 uc5 聚合池的 4,900 问中 88% 来自合成构造金标，且 UC-4（Jev 表现最弱的套件）因无金标贡献 0 问——全体聚合行不能单独作为校准证据，以真实子集行为准。

**zh↔en 对齐**（30 对，glm 翻译）：判定翻转率 6.7%（2/30），平均概率差 0.045；英文侧 acc（vs 参照）0.967。

**结论**：真实中文群聊窗口上 ECE 0.101——约为官方英文基准（0.036–0.053）的两倍，偏高自信主要来自确认带与门控（uc1a 0.133、uc3 0.102）；合成数据上 0.040 达标。zh→en 翻转率低（6.7%），无灾难性 CJK 失效。**operational 建议：中文场景使用 Jev 概率时按 ~0.1 量级的偏高自信留阈值裕量，无需翻译预处理。**

## 11. 数据质量发现（独立于 Jev 的流水线体检）

1. **候选污染**：J3 候选列表中大量 `"X is a surface form of X"` 自指边与 `batch XXXX-YYYY mentions Z` 骨架边，是门控输入质量的最薄弱环节。
2. **确认带成分**：sim ≥ 0.88 的 262 对中分析者抽样真同一率仅约 12%，且存在 0.970 相似度的硬负例（节庆名同类）——**单靠向量阈值直接合并会产生大量错并，J1 确认判断不可省略**。
3. **漏并带**：0.75–0.88 带真重复率约 3%，稀少但存在。
4. **生产注入选择噪声**：36 个注入对齐窗口的实际注入边与 Jev top-5 零重合、与 deepseek 参照亦分歧明显，且 `injected_memories` 审计表只有阳性记录（76 条）、无拒绝记录——生产门控决策质量本身存疑。

## 13. 结论与建议

1. **J1/J2（digest 解析确认与合并裁决）**：可将 Jev noul/choice 作为生产 glm 的替代或仲裁投票方，阈值 0.5 直接用；对"同一实体"变换对（UC-1s same 0.85）如需更高召回，可降阈值至 ~0.35 或提高扇出样本数。
2. **J3（检索门控）**：**不要用 p>0.5 做选择规则**；用 Jev 概率做候选排名 + top-k（k≈5，对齐生产注入上限），金标 recall@5 已达 1.000（uc3）/ 0.925（uc3s）。
3. **UC-2 三分类**："different"标签不可达；若需反向过滤，改用两个独立 noul（same?/different?）而非单 choice。
4. **先行治理候选质量**：清理自指 surface-form 边与 batch 骨架边，对所有判断点的输入都有杠杆效应。
5. **生产注入审计**：injected_memories 只记阳性；建议为门控补阴性/拒绝日志，否则无法在位评估召回。

## 14. 局限

- 金标 192 条由分析者（LLM）单一标注、未经人类复核；uc3 仅 12 窗。
- 参照模型以 glm-5.3-flash / deepseek-v4.1-flash 复刻生产 preamble，而非生产实际使用的 claude-haiku-4-5（OpenRouter 成本/可用性）——参照口径存在模型层偏差。
- 参照模型非真值且存在缺失：uc1a 2、uc1b 2、uc2 2、uc3 40、uc3s 8、uc4 31 条调用失败（API 空内容/JSON 解析异常）；uc3/uc3s 参照口径只覆盖 deepseek 选中的候选（单边）；uc4 参照指标基于 61/92 窗。所有参照派生数字均按此口径解读，与金标冲突处以金标为准。
- zh_en 翻译经 glm 完成，翻译本身引入噪声（n=30）。
- 单快照数据，未覆盖时间维度阈值漂移；uc3s/uc1s 合成数据由模板生成，难度分布与真实分布有差距。
